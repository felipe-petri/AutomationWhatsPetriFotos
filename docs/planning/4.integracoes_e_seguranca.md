# 04 — Integrações, Segurança e Conformidade (LGPD)

> **Objetivo:** Estabelecer as diretrizes de integração externa, validação estrita de contratos de dados (Webhooks), políticas de autenticação e proteção de dados sensíveis para o ecossistema `automationWhatsPetri`.

---

## 1. Topologia de Integrações Externas

O bot atua como um hub orquestrador entre a rede do WhatsApp, os gateways de pagamento e a plataforma de galerias de prova:

```
┌───────────────────────┐
│ Evolution API v2      │◄── (Webhooks / Events) ──► WhatsApp Network
└──────────┬────────────┘
           │ POST /webhook/evolution (Internal Network)
           ▼
┌────────────────────────────────────────────────────────┐
│ automationWhatsPetri Gateway                           │
│  • Validação HMAC / apikey com tempo constante         │
│  • Parser seguro de payloads (Zod)                     │
└───────┬──────────────┬──────────────────┬──────────────┘
        │              │                  │
        ▼              ▼                  ▼
┌──────────────┐ ┌──────────────┐ ┌───────────────┐
│ Gateway Pix  │ │ Alboom Proof │ │ Storage Local │
│ (Efi / Asaas)│ │ (Galerias)   │ │ / Volume      │
└──────────────┘ └──────────────┘ └───────────────┘
```

## 2. Contratos de Integração

### 2.1 Ingestão de Webhooks (Evolution API v2)

* **Endpoint:** `POST /webhook/evolution`
* **Autenticação:** Header `apikey` obrigatório validado contra a variável `EVOLUTION_API_KEY`.
* **Regra de Defesa:** O gateway utiliza comparação de tempo constante (`crypto.timingSafeEqual`) para prevenir ataques de timing.
* **Payload Mínimo Validado:**

```json
{
  "event": "messages.upsert",
  "instance": "petri_fotos_prod",
  "data": {
    "key": {
      "remoteJid": "554799999999@s.whatsapp.net",
      "fromMe": false,
      "id": "BAE5F4...128"
    },
    "pushName": "Nome do Cliente",
    "message": {
      "conversation": "Quero foto 3x4"
    },
    "messageTimestamp": 1793289600
  }
}
```

### 2.2 Prova Digital e Galerias (Alboom)

* **Natureza da Integração:** Semi-automatizada e assistida.
* **Mecanismo:**
  1. O operador do estúdio sobe o lote com marca d'água no painel Alboom.
  2. O sistema gera ou armazena o token de acesso temporário do ensaio.
  3. O bot despacha via WhatsApp o link direto estruturado: `https://galeria.petrifotos.com.br/prova/{slug_ensaio}?auth={token_temporario}`
  4. As credenciais expiram após o prazo de seleção acordado (padrão: 15 dias).

### 2.3 Gateway de Cobrança Pix

* **Fluxo:** Criação de cobrança imediata para ordens do tipo `DOCUMENT_3X4` e `PRINT_REVELACAO`.
* **Segurança:** O bot gera o payload Pix associando o `txid` ao `order_id` interno. Nenhuma ordem entra em status `PAID` por mensagem de texto do cliente; a liberação exige confirmação de webhook oficial do gateway de pagamentos.

## 3. Matriz de Segurança e Ameaças

| Vetor de Risco | Mitigação Técnica no Código |
| :--- | :--- |
| **Spoofing de Webhook** | Bloqueio de qualquer requisição que não contenha a `apikey` válida no cabeçalho ou que venha fora da rede Docker interna (`internal bridge`). |
| **Ataque de Retransmissão (Replay)** | Registro no Redis via `SETNX` de todo `message.id` com expiração de 10 minutos. O mesmo evento nunca dispara duas cobranças ou mensagens. |
| **Injeção em Payloads** | Todo input textual passa por sanitização antes de compor consultas SQL (uso de queries parametrizadas no PostgreSQL via driver/ORM). |
| **Vazamento de Credenciais** | Uso estrito de variáveis de ambiente gerenciadas no runtime (`.env` isolado no host, sem commits no Git). |

## 4. Conformidade e Privacidade de Dados (LGPD)

O tratamento de dados no `automationWhatsPetri` segue estritamente os princípios da **Lei Geral de Proteção de Dados (Lei nº 13.709/2018)**:

### 4.1 Ciclo de Vida e Minimização de Dados (Fotos Pessoais)
* **Fotos para Documento ($3\times4$, $5\times5$):** Imagens enviadas pelos clientes para confecção de documentos contêm dados biométricos faciais (dados sensíveis, Art. 11 da LGPD).
* **Política de Retenção e Expurgo:**
  * O arquivo bruto recebido via WhatsApp é salvo em volume temporário isolado.
  * O arquivo é processado e enviado para a fila de impressão da equipe.
  * **Expurgo Automático:** Um cron job noturno executa a deleção física irrecuperável do arquivo de imagem do disco em até **48 horas** após o status do pedido mudar para `DELIVERED` ou `COMPLETED`.
  * No banco de dados relacional, mantém-se apenas o registro transacional (data, valor, quantidade), sem reter a foto do rosto do cliente.

### 4.2 Dados de Menores de Idade (Eventos Sacramentais - Crisma e Eucaristia)
* O formulário sacramental coleta nome completo, paróquia, data do evento, e-mail do responsável e foto de identificação da criança/adolescente.
* **Base Legal:** Execução de contrato/solicitação dos pais ou responsáveis legais (Art. 14 da LGPD).
* **Isolamento de Acesso:** Os registros da tabela `sacramental_requests` possuem acesso restrito apenas aos operadores autenticados do estúdio, sendo expressamente proibido o compartilhamento ou uso para finalidades de marketing sem consentimento expresso em termo separado.
* **Anonimização a Pedido:** O cliente tem o direito de solicitar a exclusão de seus dados via comando no próprio WhatsApp (ex: *"Desejo excluir meus dados"*), que altera os campos nominais para `ANONYMIZED_USER` e deleta os vínculos de mídia.

## 5. Auditoria e Logs Sem Vazamento de PII

A observabilidade do sistema deve garantir rastreabilidade técnica sem registrar Informações Pessoais Identificáveis (PII):

* **Formato de Log:** Estruturado em JSON via biblioteca padronizada (Pino ou Winston).
* **Tratamento de Strings:**
  * Números de telefone (`remoteJid`) são mascarados nos logs públicos de aplicação: `55479999****@s.whatsapp.net`.
  * Nomes e comprovantes enviados nunca são impressos no `stdout`.
  * Erros de transação registram apenas o identificador técnico (`order_id`, `txid`) e o código HTTP/Stack Trace.
* **Logs Operacionais:** Registram apenas transições de estado (`FSM: remoteJid transitioned from IDLE to SELECTING_DOC_TYPE`).

## 6. Procedimento de Resposta a Incidentes

Em caso de suspeita de comprometimento da instância ou vazamento de chave:

1. **Revogação Imediata:** Regenerar a `EVOLUTION_API_KEY` na instância do container e atualizar o arquivo `.env` da aplicação.
2. **Desconexão de Sessão:** Desconectar a instância do WhatsApp via painel administrativo da Evolution API (`DELETE /instance/logout`).
3. **Isolamento de Rede:** Desativar temporariamente o container da aplicação enquanto os logs de acesso reversos são inspecionados para identificar a origem das requisições anômalas.
4. **Relatório de Impacto:** Verificar se houve extração de dados nas tabelas `photo_orders` ou `sacramental_requests` e notificar os titulares impactados se aplicável.
